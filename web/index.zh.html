The Wrong Assumption

人类工具，是给有手、有眼、有记忆的人设计的

不是「给工具加个 API」的问题。人类工具的每一条交互假设，放在 LLM 身上都不成立。

所以六合线做的不是「更强的工具」，而是三套补偿机制 + 一条会交还的任务线。

The Graph

「图」不是比喻，是索引里的数据结构

不是画给投资人看的示意图。索引里存的是符号、引用和文件依赖——nodes、edges、cycles，可以查询、可以算影响面。

一个入口，13 种问法

默认档不需要记忆 44 个工具名。只读快查全部收进 code_query：

边界写清楚

动态调用、反射、跨语言引用不可见——这是静态分析边界，写在每次返回的 limitations 里，不装作全知。

宁可如实说“看不见”，也不让模型基于一张假图做决策。

The Six-He Line

默认档只有一条线：从一句话，到一份证据

五步主链、四个回退环、六个侧出口。每一步都写明走到了哪个 node，下一步由 next_action 给出。

One Real Run

一次真实任务，十次往返

下面每个箭头都是实际会发生的调用。中间有一次失败的检查、一次修复和一次重验——没有一步靠模型自认为完成。

写前有锚点

没有 read_ref 就不给写；文件在中间被外部改过，会直接 VERSION_CONFLICT，不静默覆盖。

失败不会被说成完成

测试失败后 progress 仍是 partial，next_action 指回同一个检查范围——先修，再证明。

收口是一个空动作

next_action:null + host_required：工具宣布「机械要求已满足」，业务是否达标由宿主判断。

When Is It Done

跑过了，不等于改对了

「完成」不是一个感觉，是一个可以检查的投影。所有状态机汇成同一个只读结论，按固定优先级取值——第一个命中的就是事实。

收口时，模型真正拿到的字段

{
  "progress": "done",
  "next_action": null,
  "mechanical_requirements_met": true,
  "goal_judgment": "host_required"
}

这四行是合同，不是文案：next_action:null 表示工具侧没有下一步；是否真的达成业务目标，工具不替你盖章。

review 路线是例外

测试全绿也不算完成——完成态由 audit 驱动。仅当审计证据适用于当前 goal 和文件时，才进入 awaiting_decision。

Architecture

一层入口，四层底座

入口可以很少，是因为复杂度被放到了它该在的地方：状态落盘、索引与解析在进程外。

状态在进程外

MCP 进程崩了，任务不会跟着丢。重启后按 journal 对账，能恢复就恢复，不能就标 indeterminate。

解析在进程外

tree-sitter 跑在 Rust 服务里，panic 被 catch_unwind 兜住，返回错误码而不是带走整个 MCP 进程。

写入是单写者

写锁 + 批次锁 + 原子写。sql.js 后端下第二个写进程会被明确拒绝，而不是悄悄覆盖。

NOTE

六合线不是把任务画成一张图。任务侧只有 route、node 和每次现算的 next_action，没有持久化的边；真正的图在代码侧——{nodes, edges, cycles}。这个区分我们写进文档，不混着说。

Proof

上下文，是 LLM 最贵的资源

工具目录每一轮都会随上下文重发。先算这笔账，再谈吞吐。

默认档目录税

16.5KB ≈ 4.86k tokens/轮
描述 2.0 KB ≈ 0.60k inputSchema 14.5 KB ≈ 4.26k（88%）

结论有点反直觉：砍描述最多只能省 0.6k。要降目录税只能砍参数面——这就是 13 个入口把 44 个工具的 schema 收进来的意义。

固定编辑路径：6 步 → 3 步

同一脚本化路径，非宿主对照，非 agentic 对话结果。

旧六步链6 调用 · 7,673 chars
新原语3 调用 · 2,662 chars
token ↓65.3% 调用 ↓50.0%
BATCH EDITS

一次多处编辑，省下的是九整轮上下文

code_batch 把 N 处编辑收进一次调用（全有或全无）。 逐处改，每一轮都要重发系统提示、工具目录、对话历史和已读文件；批量改只发一次—— 少 N−1 轮，乘的是整段上下文，不是目录税——也少 N−1 次模型往返的等待。

省下 ≈ 9 × 单轮完整上下文（10 处编辑）
单轮 20k / 50k / 100k → ≈ 180k / 450k / 900k tokens
估算；目录税 4.86k/轮 只是其中固定的一小块
逐处编辑 10 轮 · 每轮重发完整上下文
code_batch 1 轮 · 只发一次
省下 9 次整段上下文重发
同样的 10 处编辑；批量失败则整批回滚，不会留下半套改动。

Get Started

现在就可以接上

不需要构建产物。clone、装依赖，把 MCP 客户端指向它。

bash标准安装（better-sqlite3 完整后端） 
# 1) 克隆
git clone https://github.com/wulun811/LiuHe.git

# 2) 安装（含 better-sqlite3）
cd LiuHe/malong && npm ci

# 3) 启动 MCP server
node --max-old-space-size=512 mcp-server.js \
  --workspace /path/to/project
opencode.json
{
  "mcp": {
    "malong": {
      "type": "local",
      "command": ["node", "--max-old-space-size=512",
                  "malong/mcp-server.js",
                  "--workspace", "."],
      "enabled": true
    }
  }
}

The Wrong Assumption

Human tools were designed for people with hands, eyes, and memory

This is not a matter of adding an API to a tool. Every interaction assumption built into human tools fails when the user is an LLM.

What human tools assume
The LLM reality
What the Six-He line does
has hands: point, drag, confirm, trial and error

code graph + budget truncation

So the Six-He line is not a “stronger tool”. It is three compensation mechanisms plus a task line that hands control back.

The Graph

“Graph” is not a metaphor. It is a data structure in the index.

Not a diagram for the pitch deck. The index stores symbols, references, and file dependencies — nodes, edges, cycles — that you can query and run impact analysis on.

Boundaries stated plainly

Dynamic dispatch, reflection, and cross-language references are invisible — a static-analysis boundary, written into the limitations of every response. No pretending to be omniscient.

Better to say “can't see it” than let the model decide on a fake graph.

One Real Run

One real task, ten round trips

Every arrow below is a call that actually happens. In between: one failed check, one fix, one re-check — not a single step relies on the model believing it is done.

An anchor before any write

No read_ref, no write. If the file changes externally in between, you get VERSION_CONFLICT — never a silent overwrite.

Failure is never called done

After a failed test, progress stays partial and next_action points back to the same check scope — fix first, then prove.

Closing is a no-op

next_action:null + host_required: the tool states that mechanical requirements are met; whether the business goal is met is the host's call.

When Is It Done

It ran. That does not mean it is right.

“Done” is not a feeling. It is an inspectable projection. All state machines collapse into one read-only verdict, resolved by fixed priority — the first match is the fact.

Top to bottom, the first state that matches is the current fact. Read-only, not writable.

What the model actually receives at close

{
  "progress": "done",
  "next_action": null,
  "mechanical_requirements_met": true,
  "goal_judgment": "host_required"
}

These four lines are a contract, not copy: next_action:null means the tool has no next step; whether the business goal is truly met is not something the tool signs off on.

The review route is the exception

Green tests are not enough — completion is driven by audit. It enters awaiting_decision only when audit evidence applies to the current goal and files.

Architecture

One entry layer, four foundation layers

The entry layer can stay small because the complexity sits where it belongs: state on disk, index and parsing outside the process.

State lives outside the process

If the MCP process dies, the task does not go with it. On restart it reconciles against the journal: recover what can be recovered, mark the rest indeterminate.

Parsing lives outside the process

tree-sitter runs in a Rust service; panics are caught by catch_unwind and returned as error codes instead of taking the whole MCP process down.

Writes go through one writer

Write locks, batch locks, atomic writes. On the sql.js backend a second writer process is explicitly rejected — not quietly allowed to overwrite.

NOTE

The Six-He line is not a task drawn as a graph. On the task side there is only route, node, and next_action computed fresh each call — no persisted edges. The real graph is on the code side: {nodes, edges, cycles}. We put that distinction in the docs rather than blur it.

Proof

Context is the most expensive resource an LLM has

The tool catalog is re-sent with context on every turn. Do that math before talking throughput.

Default-tier catalog tax

16.5KB ≈ 4.86k tokens/turn
descriptions 2.0 KB ≈ 0.60k inputSchema 14.5 KB ≈ 4.26k (88%)

The counterintuitive part: trimming descriptions saves at most 0.6k. The only way to cut the catalog tax is to cut the parameter surface — which is exactly why 13 entries absorb the schemas of 44 tools.

The fixed edit path: 6 steps → 3 steps

Same scripted path — not a host-side baseline, not an agentic conversation.

old six-step chain6 calls · 7,673 chars
new primitives3 calls · 2,662 chars
token ↓65.3% calls ↓50.0%
BATCH EDITS

Multi-site edits save nine full rounds of context

code_batch packs N edits into one call (all or nothing). Edit site by site, and every turn re-sends the system prompt, tool catalog, conversation history, and the files already read; a batch sends once — N−1 fewer turns, multiplied by the whole context, not by the catalog tax — and N−1 fewer model waits.

saves ≈ 9 × full per-turn context (10 edit sites)
per-turn context 20k / 50k / 100k → ≈ 180k / 450k / 900k tokens

Get Started

Wire it up now

No build artifacts. Clone, install dependencies, point your MCP client at it.

# 1) clone
git clone https://github.com/wulun811/LiuHe.git

# 2) install (includes better-sqlite3)
cd LiuHe/malong && npm ci

# 3) start the MCP server
node --max-old-space-size=512 mcp-server.js \
  --workspace /path/to/project

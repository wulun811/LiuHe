## 五、边界处理原则（什么时候该停）

1. **已有清晰错误语义 + 测试锁定** → 边界已闭合，不再投入（如 BATCH_LOCK_BUSY、VERSION_CONFLICT、tsc_not_found）
2. **设计声明的局限** → 不是缺陷，不改（dynamic_calls_invisible、形状级检查、语言栈限制）
3. **存疑记录** → 有真实用例才补，无用例不臆造（残留清单 #1/#2/#7）
4. **协议/环境硬限** → 文档语义明示即可（120s 超时、tsc 依赖、sql.js 单写者）
5. **新的真实缺陷** → 止血规则：小批次修复 + 失败路径测试锁定

> 维护约定：新工具/新边界必须登记本矩阵（设想 → 覆盖 → 残留），否则视为未纳入排查面。
